# Деплой на VPS (шаг 6, #33)

Файлы каталога описывают инфраструктуру; пишет их только агент, а применяет — человек
под своей учёткой на VPS. Данные приложения хранятся в памяти процесса:
перезапуск контейнера **сбрасывает все типы встреч и брони**.

Публичная ссылка после выката: <https://hexlet-ai-386.6411130.xyz>.

## Что должно быть готово на VPS (человек, один раз)

1. Учётка без sudo для повседневных шагов и вход в группу `docker` (или команды ниже
   запускать через sudo).
2. Docker + плагин `docker compose`.
3. Домен `hexlet-ai-386.6411130.xyz`: A-запись указывает на VPS (прописывает владелец).
4. Caddy для обратного прокси и HTTPS (установка — по инструкции дистрибутива).

## 1. Образ: собрать или перенести

Вариант А — сборка прямо на VPS (там копия репозитория):

```bash
git clone https://github.com/azeos1101/ai-for-developers-project-386.git
cd ai-for-developers-project-386
docker build -t hexlet-ai-386:latest .
```

Вариант Б — собрать локально и перенести образ (на VPS не нужен исходник):

```bash
docker build -t hexlet-ai-386:latest .
docker save hexlet-ai-386:latest | ssh ИМЯ_ПОЛЬЗОВАТЕЛЯ@АДРЕС_VPS docker load
```

## 2. Запуск контейнера

```bash
cd ai-for-developers-project-386/deploy
docker compose up -d
docker compose ps            # статус healthy — через ~10–15 с после старта
docker compose logs -f app   # логи puma, остановка — Ctrl+C
```

Контейнер слушает `0.0.0.0:8080` внутри себя и опубликован только на loopback
`127.0.0.1:8081` — снаружи доступен лишь через прокси. `restart: unless-stopped`
возвращает его в работу после перезагрузки VPS.

## 3. Обратный прокси (человек, один раз)

Содержимое `Caddyfile` добавить в конфигурацию Caddy (обычно `/etc/caddy/Caddyfile`)
и перезагрузить прокси, например:

```bash
sudo systemctl reload caddy
```

Caddy сам получит и продлит сертификат Let's Encrypt для домена; HTTP он сам
редиректит на HTTPS.

## 4. Проверка развёрнутого сервиса

```bash
curl -fsS https://hexlet-ai-386.6411130.xyz/api/health   # {"status":"ok"}
E2E_BASE_URL=https://hexlet-ai-386.6411130.xyz mise run test:e2e:remote
```

`test:e2e:remote` гоняет браузерный сценарий гостя и владельца по публичной ссылке:
создание типа встречи с уникальным id, запись гостя на свободный слот из календаря,
просмотр брони владельцем на «Предстоящих событиях» и отказ повторной брони (409).
Тест не требует пустого хранилища и безопасен на живом сервисе.

## Обновление версии

```bash
docker build -t hexlet-ai-386:latest .        # или docker save/load, см. п. 1
cd deploy && docker compose up -d             # compose пересоздаст контейнер
```

После обновления хранилище пусто: типы встреч создаются заново — через форму на `/events`
или `mise run setup` с `PORT`/адресом удалённого сервиса.
