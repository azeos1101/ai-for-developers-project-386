# SPA на History API с react-router и catch-all в Sinatra, /api не перехватывается

Фронтенд — один React-бандл, который отдаёт Sinatra из `frontend/dist`. Решили строить
многомаршрутное приложение как SPA на History API: Sinatra отдаёт `index.html` по
catch-all на **все** GET-маршруты вне `/api`, а на неизвестном пути фронтенд рисует
«Страница не найдена» со ссылкой на главную. Рассматривали hash-роутер (портит чистые
URL) и мультистраничку на ERB (текст виден rack-тестам, но делает React-компоненты
страниц бесполезными).

Маршрутизацию ведёт `react-router` (актуальная мажорная версия, декларативный режим с
`BrowserRouter`), а не своя микро-маршрутизация: правило проекта — стандартные решения,
которые модель знает «по памяти»; на следующих шагах появятся `?type=`, страница
владельца и переходы, свой роутер пришлось бы расширять.

Важное исключение: catch-all не перехватывает `/api/*` — неизвестный API-маршрут
отвечает 404 в JSON по модели `ApiError` (`{"code":"not_found",...}`), а не
`index.html`, чтобы API-клиент никогда не получал HTML вместо ответа. Содержимое
страниц из-за SPA проверяется браузерными тестами (ADR-0002). Приложение читает порт
из переменной `PORT` (по умолчанию 4567). Для всех маршрутов SPA до решения карты
шага 4 один статичный `<title>Запись на звонок</title>`.
