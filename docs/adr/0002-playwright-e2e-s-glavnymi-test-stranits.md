# Playwright e2e подключён на шаге 3 и является основным тестом страниц

Требование шага 3 — «главная страница открывается и ведёт на страницу записи». Rack-тест
отдачи HTML этого не доказывает: текст и ссылки живут в React-бандле (следствие ADR-0001),
поэтому решили не откладывать Playwright до шага 5, как планировалось, а подключить
сейчас: e2e-тесты на TypeScript + `@playwright/test` в отдельной папке `e2e/`, браузер
chromium, против настоящего запущенного сервера (Sinatra отдаёт собранный фронтенд), без
подмены ответов.

Граница тестирования: rack-тесты проверяют HTTP-уровень (`/`, catch-all `/booking`,
404 JSON по `ApiError` для неизвестного `/api/*`), содержимое страниц — Playwright.
`mise run check` = линтеры + rack-тесты + `build` + e2e; e2e поднимают сервер сами через
`webServer` в `e2e/playwright.config.ts` на отдельном порту (`PORT=4580`,
`reuseExistingServer: false`) — приложение читает порт из переменной `PORT`
(по умолчанию 4567; пригодится и для Docker на шаге 6). CI не меняем: workflow уже
вызывает `mise run check`. Первый e2e-тест — эталон браузерных тестов для шага 5.
Локаторы — по ролям и доступным именам: переход на запись ищется как ссылка
(role=link) с именем, содержащим «Записаться», а не по CSS-классам или структуре DOM.
