## Принятые решения (2026-11-19)

1. **Стек:** бекенд Ruby + Sinatra (JSON API + отдача собранного фронта), фронтенд **React на JavaScript (JSX) + Vite**. TypeScript не используем в своём коде: его сложно ревьюить. Клиентский SDK генерирует `@hey-api/openapi-ts` (выдаёт TS), Vite собирает его вместе с JSX без отдельной настройки; наш код вызывает только функции SDK.
1a. **Браузерные тесты (шаг 5):** TypeScript + Playwright (`e2e/`, `@playwright/test`), гоняются против настоящего запущенного сервера, входят в `mise run check`. TS здесь — только в e2e-тестах; в коде приложения — JS.
2. **Сервер по контракту:** гем `committee` в API-тестах (каждый запрос/ответ сверяется с `openapi/openapi.yaml`) + Schemathesis отдельной задачей (`mise run check:contract`, фаззинг запущенного сервера; не в каждом `check`).
3. **Сгенерированное в git:** `openapi/` и `sdk/` коммитим, `generate:check` в CI ловит расхождение.
4. **Коммиты:** Conventional Commits, текст по-русски: `feat: запись на свободный слот (#12)`.
5. **Push:** только после явного «да» пользователя на каждый push.
6. **Деплой:** фактически — свой VPS (`.44`) в Docker, домен пропишет пользователь. В README и описании проекта **Render остаётся** как путь из задания (шаблон MCP-конфигурации без секретов + инструкция), рядом — описание нашего выката на VPS и публичная ссылка.

**C–D. Грилинг и спецификация (Kimi):**
- Грилинг тратить прежде всего на **модель данных и контракт** — их потом не поменять.
- `GLOSSARY.md` маленький, в формате CONTEXT.md: термин = тип в TypeSpec, связи, неоднозначности («слот/бронь», «тип встречи/встреча», «владелец/гость»), строки `Avoid:`.
- Вопросы для карты: статусы брони — строковый enum; отмена — смена статуса, не удаление; все `@get` без побочных эффектов; «административный запрет вместо кода» (перенос = отмена + новая бронь).
- Тикеты снизу вверх, один слой — одна сессия Qwen: TypeSpec + Store → входные структуры → use cases → маршруты → фронт на SDK. **Первый тикет — эталонная сквозная фича** с эталонным API-тестом и эталонным e2e; в каждом следующем тикете поле «Образец: `@файл`».
- Тикет release-please — после первого `feat:` (иначе Release PR пустой).

**E. Реализация:**
- Слой `lib/usecases/` (`CreateBooking`, `ListSlots`), результат одной формы `Success`/`Failure`; `Failure(:slot_conflict)` → 409.
- Тесты проверяют поведение, форму ответа проверяет контракт (`committee`); Playwright — локаторы по ролям/тексту, не структура DOM.
- Именованные фикстуры, включая кейс пересечения 60 мин в 10:00 + 30 мин в 10:30; те же данные для ручной проверки (`make setup`).
- Выбор слота — изолированный компонент (`value`/`onChange`) — можно Qwen почти без ревью внутренностей, с e2e. Логика доступности и пересечений — по плану Kimi и с полным ревью.
- ast-grep: запрет `skip`/`only`/закомментированных тестов; запрет манкипатчинга `Time`/`Date`.
- release-please: разрешить Actions создавать PR в настройках репо; PR, созданный `GITHUB_TOKEN`, **не запускает CI** — решить, как проверять Release PR.
- Тикеты отдавать агенту номером (`gh issue view N`), не пересказом; правки по ревью — локально, не через `/oc` в комментариях.
- Если Qwen начнёт угадывать формы данных на фронте — `// @ts-check` + JSDoc в модулях, вызывающих SDK.

**F. Деплой на VPS `.44`:** отдельный SSH-пользователь без sudo; Compose/конфиг прокси пишет агент, применяет человек; без verbose-вывода деплоя (утечка ключей); Render MCP — только облачному агенту и только на сессию деплоя.
